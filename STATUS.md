# Sky Pie — current state

## What ships

### Chrome & navigation
- **Browser-style tabs** with per-tab back/forward history (cap 50), pure reducer (`src/state/tabs.ts`, vitest-covered), drag-to-reorder, ⌘T/⌘W/⌃Tab/⌘⇧[]/⌘1-9, middle-click close, "Close Others / Close to the Right" context menu.
- **Toolbar**: sidebar toggle, back/forward/reload, editable address bar (⌘L, accepts absolute / `file://` / `skypie://` inputs; idle it shows the **workspace-relative** path, focus swaps in the absolute path selected), bookmark star, copy path, the Share menu, the provenance badge (from <Device> / beamed / external), zoom indicator, reader-mode button.
- **View modes**: ⌘B hides/shows the sidebar (persisted, `panes.sidebar_visible`); ⇧⌘F is transient reader mode — sidebar + toolbar gone, tabs + document only; Esc/⇧⌘F/⌘L/⌘B leaves it. Both forwardable from preview iframes. With the sidebar hidden the tab strip reserves the 78px traffic-light gutter.
- **Sidebar sections**: fixed header over three collapsible drawers of one shape (`SidebarSection`, per-drawer localStorage) — Bookmarks (pinned), Recent (last 8 opened, from the recents store), Files (the whole workspace tree, **folded by default**). Retrieval order: Bookmarks → Recent → ⌘P; the tree is for walking a project.
- **Start page** on empty tabs: New York serif wordmark, bookmarks + recents lists, open/pick actions.
- **Quick open (⌘P)**: fuzzy palette over `list_files_recursive` (BFS, 20k cap, ignore/hidden/symlink policy), in-house subsequence scorer, cache invalidated by watcher events.
- **Keyboard registry** (`src/keyboard/shortcuts.ts`): declarative combos, `e.code`-based exact-modifier matching; HTML preview iframes forward tab/nav/zoom/view-mode chords plus bare Escape (bound only in reader mode) via `skypie:keydown` so those survive iframe focus (dialog/focus chords ⌘O/⌘L/⌘P are deliberately not forwardable — page content could synthesize them).
- **Per-tab zoom** (⌘+/−/0) via CSS `zoom` — host content directly, iframes via `skypie:setZoom`.

### Live reload (the headline feature)
- Workspace watcher events + dedicated `skypie://file-changed` events fan out through a subscription bus (`src/state/watcher-bus.tsx`) to (a) surgical Explorer folder invalidation and (b) tab auto-reload (150 ms/path debounce). Open out-of-root files are individually watched via `watch_external_paths` (parent-dir NonRecursive watches → survives atomic rename saves).
- **Scroll position survives reloads and tab switches**: iframe `skypie:scroll`/`skypie:restoreScroll` protocol (source-filtered), container scrollTop for md/text, `ScrollMemoryProvider` keyed `tabId::path`.
- `remove` events show a "File deleted" notice (tab kept); re-add auto-recovers.

### Explorer
- Hoisted expansion state (`ExplorerUiProvider`); `reveal(path)` expands ancestor chains in one update — the deep-link `reveal` intent works, and the active tab's file auto-reveals.
- Tree keyboard navigation (arrows/Enter/Home/End), `role=tree/treeitem`, `aria-expanded/level`, roving tabindex.
- Context menus everywhere (custom, no dep): Open in New Tab, Reveal in Finder, Copy Path, Bookmark toggle.
- Context menus carry *Copy Link for My Devices* and *Beam to Anyone…* on macOS. ("Open in Default App" was dropped in review: it required `opener:allow-open-path **`, an arbitrary-program-launch grant reachable from webview IPC.)

### Sharing — one identity per device, paired devices pull, anyone else gets a beam link
- **The model** (revamped 2026-09-12). Every install is one iroh node (`remote/identity.key`). The user's own devices are **paired** once — a `skypie://pair?ticket=…` link (or its QR code) plus a six-word fingerprint compared on both screens — and a paired device is trusted in full: there is no scope, no per-peer grant, no "control". Anyone else gets a **beam link**. All iroh types stay quarantined in `crates/skypie-remote/`, behind the `src-tauri/src/remote.rs` facade; lazy boot: zero sockets until the first remote action or, with peers and `preferences.remote_listen` (default **on**), at launch.
- **Links carry the origin device.** `skypie://open?path=<abs>&from=<node id>` (and `reveal`). `from` absent or this install's own id → a local open, as before. `from` a paired peer → `DeepLinkAction::OpenRemote` → the frontend opens a tab at `skypie-remote://<peer><path>`, whose loader calls `remote_get`: `GetArtifact` over the session (`skypie/scope/1`), then a peer-locked, BLAKE3-verified fetch over iroh-blobs into `remote/cache/<hash><ext>`. `from` unknown → `deep-link-error` "not paired with the device this link comes from", which the UI turns into a toast pointing at Settings → Devices. The tab wears a **from &lt;Device&gt;** badge (`utils/tab-badge.ts`; precedence from > beamed > external); a pull that fails renders "Device unreachable / Try again" or "Not a paired device / Open Devices…" (`read-error.ts` on the typed `remote-<cause>` kind `remote_get` rejects with).
- **Share menu.** One toolbar **Share ▾** (`ShareMenu.tsx`) replaces the three buttons: *Copy link for my devices* (⌘⇧C, also in the context menu), *Share link…* (native sheet with the device link), *Beam to anyone…*, *Share file…*, *Open in Slack* when a target is configured. The ⚡ pill stays a status indicator of active beams.
- **Devices pane** (Settings): device list with presence dot, "Online / Connecting… / Last seen … / Never connected", short id, **Unpair**; *Pair a device…* shows the invite as link + Copy + Share + **QR code** (`uqr`, inline SVG, macOS host face); *Check who's online* dials every device (`remote_connect`); *Listen at launch* stays, default on.
- **Wire protocol** `skypie/scope/1` + `skypie/pair/1`: `Req::{Hello, GetArtifact}`, `Res::{Hello, Artifact, Denied}`, one response per request, no events. The path gate for a paired peer is absolute + no NUL + canonicalize + regular file + `HARD_CAP_BYTES` — no root set, because paired means the user's own device. Grants are unchanged: `stage_for_peer` stages and admits exactly one NodeId in one operation, `GRANT_TTL_SECS` = 1 h, `revoke` cuts live sessions (`CLOSE_NOT_PAIRED`) and unpins. `ConnectError::{Unreachable, Refused, Unpaired}` decided by close code, never by the peer's text.
- **Beam** (anyone-with-the-link) is unchanged in substance: `ImportMode::Copy` staging, per-request gate that admits only a plain full-blob GET of an active offer, Stop/TTL revoke instantly, GC (`endpoint::GC_INTERVAL` 60 s) frees the bytes, boot sweeps `auto-*` tags, receive lands verified under `received/<date>/` with the **beamed** badge and hardened-iframe isolation. `BeamDialog` now has Share beside Copy.
- **Removed** (2026-09-12): the three-tier scope (`view-open`/`browse`/`control`), `last_ack_scope`, `remote_set_scope`, tab mirroring (`ListTabs`/`Subscribe`/`Event::Tab*`/`publish_tabs`), follow mode, the remote browse tree, `OpenOnHost`, `PushArtifact`/`send_to_device`, the offline outbox and its drainer, `HostCatalog`, cross-wire `FileChanged` live reload (a reload of a pulled tab re-issues `GetArtifact`), the iOS `remote_listen` adoption migration, `relay_url`. `peers.json` stays schema 1: old documents with `scope` keys load and drop them on the next write.
- **Binary-size impact**: release `skypie-app` ~28 MB with `iroh` + `iroh-blobs`; accepted for a local .app.

### MCP server (crates/skypie-mcp)
- **A thin client of the running app** (2026-09-12), with no iroh, no identity and no state of its own. The app listens on `<state_dir>/app.sock` (`src-tauri/src/ipc_server.rs`, macOS only, `0600`, one JSON line in / one out per connection, contract in `crates/skypie-ipc`); every `#[tauri::command]` is a thin wrapper over a `pub(crate) …_for(&AppHandle)` the socket dispatcher also calls, so there is one implementation per operation. `skypie-mcp` connects at the first tool call and runs `open -g -b ai.skypie.SkyPie` when nothing listens, retrying for 15 s. A stale socket file is removed; a live one from a second app instance is respected (that instance does not serve).
- Tools: `share_link` (new — a `skypie://open?…&from=` link for paired devices), `beam_artifact`, `stop_beam`, `list_devices { probe }` (online/offline/refused/unpaired/unknown, probe bounded at `PROBE_TIMEOUT` 12 s, all devices at once), `pair_device`, `pair_status`, `confirm_pairing { accept, node_id? }`, `forget_device`, `server_status`. `send_to_device` is gone: nothing is pushed, nothing is queued.
- Env: `SKYPIE_MCP_ROOTS` gates **only** `beam_artifact` (what a prompt-steered model may publish to strangers; `share_link` reaches only the user's own devices); `SKYPIE_STATE_DIR` locates the socket; `SKYPIE_APP_BUNDLE_ID` overrides the launch target. `SKYPIE_MCP_STATE_DIR` is gone; an old `SkyPie/mcp/` tree can be deleted.
- Documented in `README-MCP.md`.

### iOS companion
- Tauri iOS target builds and runs on the iPhone simulator (`scripts/build-ios-sim.sh`) and on a physical iPhone (`pnpm tauri ios build` → `devicectl device install app`).
- **`skypie://` is registered on iOS** (fixed 2026-08-30). `tauri.conf.json` declared the scheme only under `deep-link.desktop`; the plugin builds iOS `CFBundleURLTypes` from `deep-link.mobile`, and an empty `mobile` list makes it REMOVE the key (`tauri-plugin-deep-link-2.4.9/build.rs:145`). The simulator bundle carried the key from an earlier generation, so the simulator E2E passed while the signed IPA on the phone registered no handler at all and every `skypie://pair` link was dead. `"mobile": [{ "scheme": ["skypie"] }]` restores it; verified in the signed IPA.
- Receive-focused UI: `IosStartPage` ("Pair with a Mac"), `ReceivedDrawer`; macOS-only code (the share menu, the app socket) is cfg-gated out of the iOS build. A tab pulled from a paired Mac says "from <Mac>" under its title.
- Debug-only `SKYPIE_TEST_AUTOPAIR` E2E hook in `src-tauri` (three arms) — confirmed absent from release builds by running `strings` on the release binary.
- **Live simulator E2E of the pull model (2026-09-12)**: a debug Mac app over a scratch `SKYPIE_STATE_DIR` (socket `0600`, dir `0700`) minted a `skypie://pair` link through `app.sock`; the iPhone 17 Pro simulator opened it (`SKYPIE_TEST_AUTOPAIR` on both sides), `list_devices{probe}` reported the phone online, a `share_link` opened on the phone as `report.html · from <Mac>` with the file pulled from the Mac, a stranger's `from=` produced the "not paired" toast, and with the Mac quit a new link rendered "Device unreachable / Try again" after one re-dial. The pairing survived relaunching both apps. Two fixes came out of it: a cached session that died under a request is forgotten and dialed once more (`GetFailure::Closed`) instead of reading as "refused" a minute later, and a stale "Pairing request" face clears once its device is paired.
- **Phone-adapted layout** (`PhoneShell.tsx`): on iOS the desktop panes never mount. One column — a 40px title band (active artifact's basename, plus "from <Mac>" for a pulled file), the artifact full-bleed, and a bottom bar at the thumb (Library, back/forward, tab count). Library (Received + Settings) and the open-tab list are bottom sheets over a scrim; safe-area insets respected, `100dvh` instead of `100vh` (WKWebView's vh overshoots the visible viewport and hid the bar). Same design tokens as the desktop — the phone changes the architecture, not the language.
- Theme: Tauri's `window.theme()` reports "light" on iOS regardless of the trait collection, so `useTheme` skips the Tauri probe on iOS (UA check — the `platform-ios` body class arrives async and would race it) and trusts `prefers-color-scheme`, which WKWebView tracks correctly.
- **Foregrounding** (`WindowEvent::Resumed`, which is `applicationWillEnterForeground` — not `RunEvent::Resumed`, which is a poll) drops every cached session and emits a `resumed` remote event; the frontend re-dials every paired device so presence is true again, and a pull dials on its own. `preferences.remote_listen` defaults to on for every install since 2026-09-12, so the one-way adoption migration the phone needed is gone.
- The iOS companion names itself from UIKit (`src-tauri/src/device_name.rs`), not `gethostname`: the simulator announces "iPhone 17 Pro", where it used to announce the HOST Mac's name and sat in the device list indistinguishable from the Mac it was paired to. macOS still uses the hostname. Without the `user-assigned-device-name` entitlement iOS answers with the model, so two iPhones of the SAME model are still indistinguishable.

### Comments on artifacts (2026-09-13)
- **The store** (`src-tauri/src/annotations.rs`). A subset of the W3C Web Annotation model in plain JSON — the recommendation's property names and selector vocabulary, none of its JSON-LD machinery. One append-only **JSON Lines** file per TARGET under `<state>/annotations/<blake3(portable path)>.jsonl`, plus `index.json` for badge counts (keyed by store key, and holding the path portable too — an absolute path recorded there is dead after the next iOS container move). The key is canonical as well as portable: the scope gate canonicalizes, so without it a peer's comments landed under `/private/var/…` while the UI looked under `/var/…`. Append-only is what makes merging two devices a union by annotation id instead of a CRDT; a status change is a new `assessing` entry that the fold applies and then hides, so history is free. A line that does not parse is skipped, so a torn last line from a killed process costs one comment and not the file. Caps: `MAX_BODY_CHARS` 10k, `MAX_STORE_BYTES` 8 MiB.
- **Where it lives.** The state directory, never beside the user's file — the read-only-tree principle holds, external files with no project still get comments, and iOS (which has no user tree) works unchanged. `export_sidecar` writes `<file>.comments.jsonl` beside the file, on explicit request only, never automatically.
- **Anchors.** Every comment stores a `TextQuoteSelector` (exact + 32 chars of prefix and suffix), a `TextPositionSelector`, a `line=N` fragment, and the file's `blake3:` hash at comment time. Image pins are `xywh=percent:` — percent, never pixels, so a pin dropped on a phone lands in the same place on a 27" display.
- **Re-anchoring** (`src/annotations/anchor.ts`) is a ladder: unchanged hash → stored offsets are exact, no search; else the quote with its context, trimmed outside-in; else the bare quote nearest the old position; else fuzzy; else **detached** — greyed at the top of the rail, never deleted. Live reload rewrites the document under a comment constantly, so this is the feature and not an edge case.
- **The fuzzy rung** compares LINE-ALIGNED candidates within `NEAR_WINDOW` of the old offset, by Sørensen–Dice over character bigrams, re-attaching at `FUZZY_FLOOR` 0.7. Line-aligned because edits respect lines, which makes the cheap candidate set also the right one — O(lines in window) rather than O(n·m), and this runs per comment per reload. Windowed because an unbounded search on a document full of repeated table rows would jump to a lookalike forty pages away. Whitespace is collapsed and case ignored, so an agent reformatting a table changes nothing. Dice rather than edit distance: O(n), and insensitive to a moved clause, which is the edit a rewrite actually makes.
- **UI (reworked 2026-09-15).** Comments are made with a **comment tool**, not a text selection: a toolbar tile (⇧⌘K, Esc puts it down) turns the pointer into a crosshair, and a click on a line (code, text), a top-level block (rendered Markdown), an element (HTML artifact) or a spot on an image becomes the target. Code and plain text carry a GitHub-style line gutter (one `.line` span per line, numbered by CSS counters); rendered Markdown numbers each top-level block by its SOURCE line (`data-source-line`, from marked's lexer offsets — `src/render/md-blocks.ts`), so "line 42" means the same thing in the file. An HTML element stores a W3C **`CssSelector`** (`main > p:nth-of-type(3)`, cut short at a unique id) ahead of the usual quote/position/line set; the frame resolves the path first and falls back to the quote. On macOS the threads are **margin notes** (`CommentOverlay`): cards floating over the right edge of the preview, level with their anchor, pushed apart by `layoutNotes` (the active card keeps its place), with a second tile (⇧⌘M) to show or hide them; hover or activation paints the anchor in the document. Positions come from the host DOM for Markdown/code/images and from the frame (`skypie:locate` / `skypie:located`, re-sent on scroll) for HTML. iOS keeps the bottom sheet: the bar gains the tool tile, a tap on a target opens the sheet at the composer. The old selection path (`skypie:selection`, `mouseup`) is gone — it never fired on iOS, where a long-press selection produces no `mouseup`. The frame paints its hover box and the active anchor with two fixed `<div>`s appended to `<html>`, outside `<body>`; the CSS Custom Highlight API is no longer used. A root error boundary (`RootErrorBoundary`) shows a render error with its stack instead of a black window.
- **Authorship** is the iroh node id plus the device name `peers.json` already holds. No accounts.

### Claude Code plugin (`plugin/`, built by `scripts/build-plugin.sh`)
- `plugin.json` registers the MCP server; `hooks/hooks.json` registers three hooks. All four run the SAME binary — `skypie-mcp` grew a `hook <event>` subcommand, so there is one socket client, one state-dir rule, and no Node or Python at hook time.
- `PostToolUse`/`Read` and `PostToolUse`/`Write|Edit|MultiEdit` inject the file's open feedback as `hookSpecificOutput.additionalContext`. `UserPromptSubmit` adds one sentence naming up to three waiting files.
- **Two rules, both tested.** The hook is SILENT when a file has no feedback — it fires on every `Read` in every session. It NEVER launches the app: the MCP tools launch Sky Pie because a person asked for a share; an agent reading a file is no such mandate. Nothing listening means silence, exit 0. `build-plugin.sh` asserts the silence before it ships a bundle.
- New MCP tools: `list_feedback` (one file, or every file waiting) and `resolve_feedback`. There is deliberately **no** "write a comment" verb on this socket — authoring in the user's name is not something a model gets to do.
- New IPC verbs `FeedbackFor` / `FeedbackIndex` / `ResolveFeedback`; `IPC_PROTO` is now **2**.

### Feedback over the wire (decision 5)
- `Req::{GetAnnotations, PutAnnotations}` and `Res::{Annotations, Merged}`, **appended** to the postcard enums — a test pins `Hello`=0, `GetArtifact`=1, `Denied`=2, because postcard identifies a variant by declaration order and reordering would make every older peer misread every frame.
- **`PutAnnotations` is the first write this wire has ever carried**, and it is bounded on every axis: the connection already proved the peer is paired, the peer list is re-read per request (an unpair may have landed since the session opened), the path goes through the SAME `gate_raw` + regular-file check as `GetArtifact` with the same no-existence-leak refusal, and the frame is capped at `MAX_ANNOTATION_ENTRIES` 500 × `MAX_ANNOTATION_BYTES` 64 KiB with newlines refused (one entry per line is the store's whole framing). `check_entries` is shared by both ends, so a bad push fails locally with a message the user can act on instead of as an opaque `Denied`.
- **The app uses the wire now (2026-09-15).** Until this date nothing in the app called `get_annotations` / `put_annotations` — only the crate's own test did — so comments never crossed between devices, in either direction. `remote_sync_annotations(peer, path, source)` (`src-tauri/src/remote.rs`) is one idempotent pass: read the host's page, then `annotations::reconcile` off the runtime worker — `merge` the page under the tab's store (`source`, the `skypie-remote://` address the rail reads, passed through so the key is the same bytes the UI uses), then frame what the host lacks (`annotations::unseen`, a set difference by id computed against the store as it was BEFORE the merge) — and push it under the host's path. A second pass moves nothing while the host store is under the wire's 500-line page (past it, see the follow-ups), and a comment written while the host was unreachable goes out on the first pass that reaches it — no outbox. **`merge` stamps every accepted entry with the store it lands in** instead of refusing a mismatched `target.source`: the two ends name one file differently, the host's gate canonicalizes while the reader's link may not, and a refusal there read as `Merged { added: 0 }` with no error. A peer still cannot scatter comments — `source` is the caller's, never the entry's. The host serves `annotations::raw_lines` (as stored, unfolded) rather than `list`: a folded page would carry a status the reader's `merge` skips, and the `assessing` line would never cross. Bounded failure modes: a truncated page still merges but pushes nothing (a prefix is not a set); an entry the wire would refuse is left out of the frame, not blocking the rest; unreadable lines are counted and logged on both ends; `notify` fires on a failed merge too, because `merge` appends before it reindexes. `annotations::reconcile` is tested with two stores in one directory: convergence in one pass each way, replay moves nothing, a status change crosses in both directions, a truncated page pushes nothing, a refused entry does not block the frame.
- **When it runs** (`src/state/remote-comment-sync.ts`, policy in `src/annotations/sync.ts`): on open of a pulled tab, after every local write on it (a write mid-pass queues one catch-up pass), on window focus / visibility, and every `BASE_SYNC_MS` (10 s) while the window is visible. Visibility, not focus, is the gate: in a WKWebView `document.hasFocus()` is false whenever the web view is not the first responder, which on the phone would make the timer a permanent no-op. A hidden window arms no timer at all and a pending one runs no pass; a local tab is inert. The provider is mounted once for every tab, so the hook keys its in-flight guard by source and resets its backoff on a tab switch. The host side needs no poll: a push lands live through the changed event. `nextSyncDelayMs(failures)` backs off exponentially from 10 s to a 120 s ceiling after a failed pass, chosen after the pass settles; a wake runs an immediate pass, and `WAKE_GAP_MS` collapses the focus + visibility pair an app switch fires into one. Only an `unreachable` host stays quiet (local-first); a permanent cause — unpaired, refused, a store failure — lands in the provider's `error` so the rail says so.
- What a paired peer can do: add comments the user will see. What it cannot: edit or delete an existing one (the store is append-only and merges by id), or land anything outside the state directory.
- `skypie-remote` stays free of the annotation schema. Entries cross the wire as opaque strings and reach the app through a new `AnnotationStore` seam, next to `EventSink` and `Dirs`; `NoAnnotations` is the default, so a build with no comment store serves an empty page rather than a refusal a peer cannot interpret. The app's impl parses at that boundary — an entry that does not parse is dropped, not appended, or a local read would skip it forever as a corrupt line.
- `crates/skypie-remote/tests/pull_artifact.rs` drives it over two real endpoints: push, re-read, replay adds nothing, a directory and a missing file and a relative path and a NUL are all refused identically, a flood and a torn entry never reach the wire, and an unpair cuts the write path with everything else.

## Open items

- **Comment sync follow-ups**: the whole store crosses the wire on every pass (no delta; a cursor on the UUIDv7 id would make an unchanged pass a few bytes), and `read_annotations` serves the FIRST `MAX_ANNOTATION_ENTRIES` (500) lines in file order, so a host store past that never serves its tail to a reader (the reader merges the prefix and skips its push, logged once per pass) — an addressable page (`after: <id>`) is the fix. The hook's timer/wake loop is untested: extracting it to a pure function with an injected clock and event target, as `remote-reconnect.ts` does for `dialsEveryPeer`, would let vitest fake timers cover the backoff, the wake gap, and the hidden-window rule. Two devices that each open the SAME file locally (a git-synced path, no `from=` link) have no peer relation and do not reconcile; only a pulled tab does. The host learns of a peer's comments only when that peer runs a pass, so a host reading a file nobody has pulled since sees nothing new until the reader's window is visible AND the pulled tab is the active one — a pulled tab in a background tab never reconciles, because the provider only ever holds the active tab's source. A closed host Mac still costs one `DIAL_TIMEOUT` (30 s) per pass; the backoff bounds how often, not how long. Skipping the pass when presence already says offline is the next step.
- **Pull-model follow-ups**: a pulled tab does not live-reload when the file changes on the origin device (⌘R re-pulls); no per-peer fetch quota; `remote_get`'s "peer offline" wording is the crate's, not the device name's (the tab notice adds the name). `endpoint.online()` waits up to 10 s before minting a share or pair link when relays are unreachable — the link still works on the same LAN.
- **Beam follow-ups**: single-fetch mode, Settings UI for `beam_ttl_hours`, macOS application-firewall prompt doc for unnotarized inbound.
- **MCP**: the socket is reachable by any process running as this user (same boundary as `identity.key`); a `getpeereid` check would tighten it. `open -b` launches whichever build Launch Services registered last, so a dev build beside the installed .app needs `SKYPIE_APP_BUNDLE_ID` / `SKYPIE_STATE_DIR`.
- **Dropping a booted node no longer closes its blob store** — the collector task holds a store handle for the store's whole life, so the actor never sees its last sender go and redb stays open while the lock file says the store is free. A process that hands its state directory to another opener WITHIN its own lifetime must call `RemoteNode::shutdown`; the tests that re-open a store in one process are the only places this matters.
- ~~Nothing asserts the iOS scheme is registered.~~ **Fixed 2026-09-13**: `scripts/build-ios-sim.sh` now reads `CFBundleURLTypes:0:CFBundleURLSchemes:0` off the BUILT bundle and fails the build when it is not `skypie`. `scripts/install-ios-device.sh` (2026-09-14) carries the same assertion on the device path, plus an `/usr/lib/swift` rpath check — the simulator cannot catch a missing rpath, because its dyld resolves Swift from the runtime root.
- **Live PHYSICAL-device E2E of the pull model (2026-09-14)**: an iPhone 17 Pro (iOS 26.6.1), paired to the Mac app, opened a `skypie://open?…&from=` link minted by the MCP `share_link` tool over `app.sock` and rendered the pulled artifact with the **from Alvaros-MacBook-Pro** badge. First run of this path off the simulator: a simulator shares the host's network stack, a phone does not, so this is the first exercise of the iroh handshake between genuinely separate hosts. Relays are still unexercised (same local network). The deep link was delivered with `devicectl device process launch --payload-url`, which is the device equivalent of `simctl openurl` — iOS does not linkify a custom scheme in plain text, so a pasted `skypie://` link is not tappable and the QR code is the intended human route.

The rewrite runs over the whole `state.json` document as JSON rather than field by field, because the store round-trips unknown fields and `panes.tabs` is an opaque blob Rust never models.
- **Relative subresources in HTML artifacts do not load (found 2026-09-15)**: `src/render/html.tsx` injects `<base href="file://<dir>/">` so a relative `<img>`, `<link>` or `<script>` resolves against the artifact's folder, but the srcdoc frame inherits the app origin (`tauri://localhost`, dev `http://localhost:1420`) and WebKit refuses `file://` subresources from a non-file origin. Seen with `branding/sky-pies-logo-sheet.html` referencing `sky-pies-logo.svg` beside it: blank in the app, fine in Safari. Inline SVG and `data:` URIs are unaffected. Workaround until then: artifacts stay single-file, which the `html-artifact` convention already requires.

## Open items — the product pivot (13 Sep 2026)

Decisions and their rationale live in `product-plan-notes.html`; `PRODUCT.md`
has been rewritten to match.

**Code still open:**
- The wire messages exist and are tested end to end, but **nothing calls them
  yet**: no Tauri command, no UI, and no offline queue for a phone that
  commented while the Mac was asleep.
- Known gaps in the 2026-09-15 comments rework: no Rust `CssSelector` arm (the `Other` arm round-trips it, so nothing is lost); a pin on an image file paints the whole image, not the spot; note alignment is unverified at a zoom other than 100%; on iOS the tapped block keeps its `:hover` paint until the next tap; and a `skypie://pair` dial from an already-paired phone raises a "Confirm pairing" dialog on the Mac that neither Confirm nor Decline can clear (autopair had already resolved it) — seen with the simulator, predates this work.
- **Review of the rework found six real bugs, all fixed in the same PR** and worth recording because each is a trap the next change could fall into. (1) Any `.line` span made the host locator call the whole document a code file, and shiki emits those into rendered Markdown — one fence sent every note on the file into it; blocks now win over lines on both the placing and the picking side. (2) Wrapping each Markdown token in a `<div>` to carry its source line split raw HTML that spans tokens, so a `<details>` body escaped its disclosure; the line is carried by an HTML COMMENT now, which nests inside nothing. (3) `blockLines` matched `token.raw` against the unnormalised source, but marked normalises CRLF inside `raw`, so every block in a Windows-authored file drifted a line per blank line. (4) The frame's anchor cache observed `document.body` from a script that runs inside `<head>`, where it is still null — the observer never attached and a resolution MISS was cached for the life of the frame. (5) That cache was keyed by id alone while the composer reuses one id, so the second pick in a generation was answered with the first one's element. (6) The margin-note height cache dropped its callback on every detach, which is the identity-churn loop the cache exists to prevent, reached from the code meant to bound its growth.
- **A pin is not a text anchor.** `reanchor` has a `region` rung so a pin never runs down the text ladder and reports "the text this comment pointed at is no longer in the file" one second after it was dropped — the same false-data-loss trap the `detached`/`unknown` split was built for. Pins also store a `CssSelector` for the image they landed on; before that, every pin in a document resolved to the first image and the identity was never written, so the mis-attachment could not be recovered.
- The comment overlay passes `contentHash: null` — `FilePayload` carries no
  hash, so the cheapest rung of the re-anchor ladder never fires and every
  reload runs the quote search. Correct, just not as fast as it should be.
  The `blake3:` hash stored on every comment is therefore still unread.
  (Review caught the sharper half of this: the rail also had no document text
  until the user selected something, so every comment on every file rendered
  as detached with a false "the text is no longer in the file" note. The
  preview now reports its rendered text on load, and an unplaced comment with
  no document to search answers `unknown` rather than `detached`.)
- No sidebar badges yet: the index is fetched and `openCountFor` exists, but
  the Explorer and Bookmarks rows do not render a count.
- The iOS plugin builds (`scripts/build-ios-sim.sh` reaches `** BUILD
  SUCCEEDED **` and the bundle registers `skypie://`), but it has not been
  RUN on a simulator yet.
